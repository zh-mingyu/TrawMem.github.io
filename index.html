TrawMem: Reframing Agent Memory as Task-Oriented Role-Adaptive Workspaces

Mingyu Zhang1, Zixu Li1,†, Zhiheng Fu1, Zhiwei Chen1, Jinhe Bi2, Yupeng Hu1,✉
1School of Software, Shandong University 2National University of Singapore
†Project leader    ✉Corresponding author
arXiv Code BibTeX
arXiv:2610.36918

Abstract

Large language model (LLM) agents rely on memory systems to leverage long-term interactions, yet existing systems typically retrieve memories based on their relevance to the current query and use them as contextual evidence. However, relevance alone does not characterize how a memory contributes to task solving: the same memory may serve different roles across tasks, such as directly supporting the answer or linking to complementary memories with weaker semantic relevance but necessary information. We therefore reframe agent memory systems as Task-Oriented Role-Adaptive Workspaces, where memories are selected and organized by their task-oriented roles and relations. Based on this view, we propose TrawMem, which organizes interaction histories into local threads and constructs task-oriented workspaces by assigning roles and jointly selecting complementary memories. Experiments on LoCoMo and MemGallery with four open- and closed-source backbones show consistent improvements over representative memory systems, with macro-F1 gains of 2.23–3.14 points. On LoCoMo, TrawMem improves the LLM-Judge score over SimpleMem by 4.07 and 4.31 percentage points on Qwen3.5-9B and DeepSeek-V4-Flash, respectively, while requiring approximately 12.8% and 5.1% fewer context tokens. Code is available at github.com/zh-mingyu/Traw-Mem.

Same Memory, Different Roles

A memory may directly answer one task, only bridge another, or merely supply temporal context. TrawMem therefore selects and organizes memories by the roles they play for the current task, rather than by relevance alone.

Method

Figure 2. Stage 1 organizes the interaction history into local threads and a thread graph. Stage 2 localizes a thread neighborhood for the current task, estimates the task's role demand, assigns query-local roles to candidate memories, and assembles a bounded workspace for the answer model.

  • Source-faithful local threads. Interaction histories are segmented into contiguous event threads, each with a routing synopsis and an ordered ledger of the original turns. Turns are never rewritten into query-specific semantic memories.
  • Persistent sparse thread graph. Threads are connected by chronological and semantic relations, so retrieval traverses a structure instead of a flat vector index.
  • One route + bounded expansion. A single routing pass localizes the task-relevant neighborhood and expands it under hop-count and neighborhood-size limits.
  • Query-local roles. Candidate memories receive Anchor / Bridge / Context roles conditioned on the query's demand; roles are frozen for the workspace and discarded afterwards.
  • Structured coverage selection. Workspace construction maximizes a monotone submodular coverage objective under a budget, preferring complementary over redundant memories.

Results

LoCoMo

Table 1. Macro-averaged LoCoMo results over four question types. F1, BLEU-1 (B-1), and LLM-Judge (J) are reported. Bold / underlined values are the best / second-best results.

TrawMem achieves the best average F1, B-1, and J under all four backbones — up to +3.14 macro-F1 over the second-best baseline, with the largest gains on Temporal questions.

MemGallery

Table 2. Macro-averaged MemGallery results for four answer backbones over nine question types.

Across all backbones TrawMem ranks first in F1, B-1, and J, with gains of +0.30–5.45 / +1.36–2.96 / +0.52–4.82 points over the second-best baseline.

Efficiency

Table 3. Efficiency and answer quality on LoCoMo. Times are s/root; answer-context tokens are tok/q; H is the maximum thread-neighborhood expansion depth.

Compared with SimpleMem, TrawMem (H=3) uses 12.8% / 5.1% fewer answer-context tokens on Qwen3.5-9B / DeepSeek-V4-Flash while scoring +4.07 / +4.31 J points higher.
